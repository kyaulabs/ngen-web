# Development

This is a static site adapted from `kyaulabs/prism-web` under AGPL-3.0. It uses vanilla JavaScript, Sass, and the reference site’s vendored D3 v7. nginx serves the built files directly; Node.js/npm are build/test tooling only, not the website’s runtime. There is no upstream application server. The complete NGEN Graphite 1.2 brand pack is retained unchanged in `brand/` (121 files).

```sh
npm ci
npm run build
```

Use [NGINX.md](NGINX.md) to build and serve a checkout at `/nginx/git/ngen-web`. `npm run build` runs UglifyJS for the two application scripts and Sass with compressed output for `styles.scss`. The Sass entry point defines the supplied brand’s dark palette unconditionally (page `#202124`, panel `#2A2B2F`, Slate header `#3A414E`) and produces one `styles.min.css`; edit the SCSS source, never the generated CSS. Sass is a build-only dependency. The build also disables source maps and error stylesheets, and exits nonzero on invalid Sass.

`index.html` loads only minified scripts and CSS. Generated application scripts and CSS are ignored by Git, so every deployment must install build dependencies with `npm ci --include=dev` and run `npm run build`. nginx serves those outputs directly, with no source aliases or application server. Browser tests use the same generated files. There is no theme switch, preference manager, or theme bootstrap script; stored light preferences and OS color schemes do not affect the page. Original light assets remain only in the supplied brand pack, not in the active page or compiled stylesheet.

Application asset URLs carry the website version as a cache key so returning visitors cannot reuse the old light stylesheet or theme manager. When preparing a release, update their `?v=` values in `index.html` with the package version; browser tests enforce this.

```sh
npx playwright install chromium
npm run check
node_modules/.bin/playwright test visual_review.spec.mjs --workers=1 --output tests/Browser/Screenshots/.playwright --reporter=line
```

Playwright automatically starts the loopback-only `tests/server.mjs` helper for browser verification. That Node.js process is test infrastructure, not an application server or deployment target.

The check runs ESLint, Vitest with 95% aggregate coverage thresholds, the production build, and Chromium browser tests. Browser tests intercept all external traffic with controlled fixtures. Screenshots under `tests/Browser/Screenshots/` are ignored working evidence. See `DESIGN.md` for the user-approved reference and viewport matrix.

Repository metadata comes from the unauthenticated GitHub REST API, cached in session storage for ten minutes. On failure, counters use the dated public snapshot in `data/snapshot.json`, embedded in `app.js`; missing record feeds remain unavailable rather than simulated. Refresh both copies together. GitHub may return pending weekly statistics; the page marks them unavailable. Daily matrix cells estimate a distribution from weekly totals and are not exact daily observations.

`space.js` uses the existing vendored D3 to generate 900 stars, blue/cyan/purple/magenta/pink nebula clouds from density contours with fractal displacement/texture, and three rotating elliptical tracks with bright stellar cores and colored fading coronas behind the supplied N artwork. The Graphite-backed star/nebula backdrop is viewport-fixed behind the hero and dashboard throughout the dark-only site, ending visually at the opaque dark footer. Panels, section headings, and unboxed text use the dark brand palette. The user-selected Prism-like treatment retains visible borders and shadows, filled controls and a cyan/violet primary action. The latest approved `--panel` fill is 60% Graphite (replacing 88% after the 65% preview); its existing button, chip and panel consumers share this background alpha without fading text. Slate titlebar/secondary fills remain 85%, and all other styling is unchanged. The N and orbital tracks remain inside the hero, and navigation always uses the dark-background wordmark. Browser-native animations move HTML layers around the star/nebula SVGs for visible drift and gentle cloud flow, independently of the 30 fps orbital timer. The static cloud gradient uses the user's requested color families, expanded from the brand cyan/violet only within the illustration; UI and logo tokens remain unchanged. It is painted once through a textured density mask rather than separately on every contour, reducing high-resolution overdraw. A centered radial corona around each white-hot orbital point replaces reflective sphere shading. Cloud geometry and filter parameters do not change during animation. All motion pauses for reduced motion, hidden tabs, or the pause control. Without the native animation API, the backdrop remains static. The orbital timer ceiling is not a frame-rate guarantee. High-resolution headless profiling remains slow; hardware-accelerated desktop performance has not been measured. UI and nebula colors retain the dark brand tokens; no WebGL or new runtime dependency is required. `assets/ngen-orbital-core.svg` contains only the supplied N and its unfilled frame, so static orbit fragments cannot show through the transparent center beneath D3’s animated tracks. If D3 or JavaScript is unavailable, `assets/ngen-orbital-fallback.svg` remains visible: it derives from the supplied dark schematic with only its captions removed and central frame fill set to `none`. Keep this site-specific variant outside the untouched brand pack.

Stars use seven approximate blackbody sRGB tints (3,000–20,000 K), separate from the UI/nebula palette. NASA's [stellar spectra explanation](https://science.nasa.gov/asset/webb/continuous-spectra-blackbody-curves-of-stars/) describes the temperature/color relationship; its [star types reference](https://science.nasa.gov/universe/stars/types/) notes that cool red stars actually appear more orange. A synthetic, faint-heavy apparent-magnitude sample uses the logarithmic flux law `10 ** (-0.4 * magnitudeDifference)`. A compressed display exposure maps flux into point-spread radius and opacity; only sparse bright sources receive radial bloom and small white highlights. These are unresolved points, not stellar disks, and no artificial twinkling or diffraction spikes are added. Temperature weights, exposure and camera drift are illustrative—not a catalog, physical stellar motion or calibrated photometry. The approved nebula geometry, spectrum, texture, opacity and animation remain unchanged; its random stream is separate from stellar sampling.

The public default branch can differ from local engine development. Language counters describe the public default branch, not the engine’s intended implementation language. No game projects have been announced for the directory. Absolute Open Graph image/URL metadata remains to be configured for the production origin.
