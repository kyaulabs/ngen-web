# Development

This static site adapts `kyaulabs/prism-web` under AGPL-3.0. It uses vanilla JavaScript, Sass and vendored D3 v7. nginx serves generated files directly; Node.js/npm are build/test tools, not production runtime. There is no application server, framework or database.

```sh
npm ci
npm run build
```

`npm run build` uses UglifyJS for `space.js` / `app.js` and compressed Sass for `styles.scss`. Edit sources, never ignored application bundles. Invalid Sass exits nonzero without an error stylesheet or source map. Every deployment needs `npm ci --include=dev && npm run build`; see [NGINX.md](NGINX.md).

The website is dark-only. Its Prism-derived palette uses #04060C page/backdrop/footer, 66% #0A101D panels, 55% #10182A headers, and 14% / 30% #7D9BD2 borders. Panel borders strengthen and the `::before` hairline appears on hover. Content remains opaque. Dialogs and tooltips use opaque panel solids. Preserve Prism’s neutral-link versus secondary-text hierarchy: links remain #A4B5CF, while `--ink-2` mixes 78% #637391 / 22% #A4B5CF (approximately #71829F). This is the minimum whole-percent mix toward muted ink clearing 4.5:1 on the three solid page/panel/header bases, not a guarantee over arbitrary imagery. Primary/default `--ink-0` retains Prism’s exact #EAF2FF, as requested after reviewing the darker variant. Raw brand pigments and accent-link colors remain unchanged. Stored light preferences and OS color schemes cannot activate a light website theme.

Neo Sans Pro and Operator Mono are self-hosted under `brand/web/fonts/`, copied unchanged from the user-provided Prism checkout. Their embedded licensing terms remain separate from the website license. Font Awesome Free **7.3.1** is a new vendored UI dependency: `vendor/fontawesome-icons.svg` contains 25 official, unmodified SVG paths grouped into local symbols. `vendor/fontawesome-LICENSE.txt` retains its notices; SVG icons are CC BY 4.0. There is no remote icon kit, CDN request or new npm/runtime dependency. Charts and space artwork remain SVG/D3, not icon replacements.

Shared controls retain Prism’s scoped styles: unframed yellow profile hints, compact copy/release controls, underlined selected tabs and gradient release tags. Do not restyle every native button with `.btn` properties: that previously capitalized tracker titles and framed unrelated hints/cards. Tracker rows remain borderless, with hover fill and inset focus. The contributor’s Font Awesome profile chevron is scoped to 0.67em with a -0.08em baseline offset, matching Prism’s text `»` ink geometry rather than a full-em UI icon. Popup close controls show the reference’s 10px traffic light inside a 24px hit target; the X appears on hover/keyboard focus. Scrolled header actions are transparent until hovered; pause/play retains intrinsic width and compact height.

The hero uses naturally sized grid rows. Mirrored `1fr` rows previously duplicated the tall lower block above the orbital N and pushed actions off a scaled laptop viewport. Test CSS viewport size separately from device scale: 3840×2078 physical pixels at 2× scaling is 1920×1039 CSS pixels. Do not compensate with CSS zoom or device-pixel-ratio scripts. Short/narrow layouts may scroll naturally; hero overflow must not clip actions.

Brand **1.4** refreshes both Prism-derived reference palettes, typography, colored masters and matching exports. Original paths, logo geometry and monochrome assets are preserved; the original supplied Graphite 1.2 archive is untouched. The active website stays dark-only even though the reference handoff supports both themes. Light cyan actions use dark ink and light status labels retain higher-contrast semantic colors.

Brand authoring is separate from deployment:

```sh
npm run build:brand
```

This optional command uses installed Playwright/Chromium, `rsvg-convert`, `pdftocairo` and ImageMagick (`magick`). Leave port 4173 free. Edit `brand/web/ngen-tokens.json`, affected SVG masters and `brand/guide/ngen-brand-guide.html`. The exporter derives reference CSS and both swatch sheets from JSON, includes the website’s font-face declarations, rebuilds colored raster/ICO counterparts at their existing dimensions, and exports the eleven-page guide to PDF/SVG/PNG. It uses task-local Fontconfig/cache files and never installs fonts globally. Monochrome exports are not regenerated. Commit versioned brand outputs; do not hand-edit generated CSS, swatch SVGs, PDF or guide page exports. Reference CSS/JS are not application source aliases; browser tests supply their actual bytes at that boundary.

Application CSS/JS URLs carry the website version as `?v=`. Update these with the package version for a release; browser tests enforce equality. Website, engine and brand versions are independent.

```sh
npx playwright install chromium
npm run check
npm run test:visual -- --case branches
```

Checks run ESLint, Vitest with ≥95% aggregate coverage, production builds and Chromium tests. Playwright starts the allowlisted, loopback-only `tests/server.mjs`; it is not a deployment server. Browser tests intercept external traffic with controlled fixtures. Ignored captures under `tests/Browser/Screenshots/` are working evidence, not user approval or full accessibility/performance certification. See `DESIGN.md` for the approved reference and viewport/state matrix.

Visual review is component-based tooling, separate from behavioral regression tests. `visual_review.json` defines reusable component cases, states and selectors; the generic runner shares the configured viewports, actions, network fixtures and contained evidence publisher. Add or update a case instead of writing a temporary capture script.

```sh
npm run test:visual -- --list
npm run test:visual -- --case branches
npm run test:visual -- --case branches --state dark --viewport mobile
npm run test:visual
```

The command builds fresh application assets before capture. `--list` only lists cases; it does not build or launch Chromium. Repeat filters to include multiple values. Unknown filters and empty selections fail, rather than reporting a successful zero-test run. With no filters, run the full matrix. For localized changes, inspect the affected component's required states at mobile, desktop and 320px reflow; use the full matrix for shared tooling or cross-cutting changes.

Reusable cases cover section headings, milestone objectives/Kanban, release notes/changelog/code copying, branch authors/checks, Games commands, activity, the matrix, footer/ticker links, contributor commit links and contributor cards. Branch states include passed/pending, failed, absent, unavailable, offline and keyboard focus; their controlled fixtures live in `tests/network.mjs`. A case can set `"captureSelector": "#branches-list"` to capture one unique component directly. A component created or revealed by actions, such as a modal, is captured after those actions; pre-position only already-visible components. Component captures clip the prepared viewport without re-scrolling or full-document resizing that could lose hover. The publisher waits for the component’s opening frames and finite animations before measuring, and rejects edges obscured by another element, such as the fixed ticker. Use an explicit `scroll-into-view` action to center an expanded component before capture; apply any hover action after repositioning. The selected component must fit inside the viewport; oversized/offscreen targets fail rather than publish a partial crop. Use a smaller component or omit the selector for a full-page case. Omit it for the existing full-page capture. Both modes retain loopback-only navigation, controlled fixtures, page-error checks and the same safe evidence publication. Metadata records `fullPage: false` for component captures without storing raw selectors. No crop helper or new dependency is needed. Evidence remains ignored; user visual acceptance is separate from passing checks.

The browser calls GitHub’s public REST API directly on page load and for on-demand details. There is no periodic polling or server-side fetch. Successful JSON responses fetched through the shared API client are cached in session storage for ten minutes. Failure uses the dated public snapshot in `data/snapshot.json`, embedded in `app.js`; refresh both together. Missing feeds remain unavailable, not simulated. Activity uses SHA-pinned default-branch history, including merges, grouped by UTC committer date into 52 Sunday-first weeks. Pagination reads 100 commits per page, up to ten pages; a failed, malformed or truncated history is unavailable, never a partial total. Weekly totals and matrix cells share these actual counts, replacing stale participation statistics and estimated daily allocations. Month labels and chart tooltips use UTC. Narrow matrices retain readable cells in a keyboard-scrollable plot, initially positioned at the latest weeks. Public languages describe the public default branch, not necessarily the engine’s intended implementation language. The game showcase remains empty until projects are announced.

Release notes omit the redundant leading NGEN logo paragraph/picture. `Markdown.splitRelease` separates an actual Changelog heading and its section from the remaining notes, ignoring fenced/commented examples. A header button opens that history in the contributor-style dialog without toggling the release. Both views use escaped markdown; raw upstream HTML stays disabled. Fenced code retains literal comments and whitespace, uses Games-command styling, and copies the complete block with local success/failure feedback. Table filenames link only when they match an actual asset URL for the same engine repository, release tag and filename; unknown files stay literal.

Milestones and the public NGEN Roadmap organization project #4 load independently through unauthenticated REST. Kanban is the first tab; Milestones opens by default. Only the selected milestone is rendered and its expanded Objectives load its issues/PRs. Native progress bars use GitHub’s milestone counters. Failed objective requests can be retried by reopening. The rail maps milestone numbers to first appearances in the engine’s `docs/planning/execution-order.md`; unlisted milestones follow by number. `Current` is configured in `app.js` (C1, #11), not inferred from board status. If that milestone is absent or closed, the first listed marker opens without a `Current` badge. Kanban reads the project’s actual status definitions and explicitly requests those fields with its cards. It excludes archived/foreign cards, preserves issue state separately from board status, and filters by actual milestone membership. Missing/unknown statuses get separate columns, not invented Todo assignments. Empty and unavailable feeds remain distinct; neither uses snapshot or fabricated progress. List pagination follows only the same resource/query, caches pagination metadata separately, and rejects cycles or a ten-page limit instead of publishing partial lists. Editing remains on GitHub; no credentials, backend or new dependency is required.

Branch cards use each HEAD commit’s committer timestamp, labelled “committed”, not repository-wide `pushed_at`. Reuse matching commits from the existing feed; fetch missing HEAD metadata by SHA through the same cache. Failed or invalid metadata leaves the time absent without hiding the branch or substituting another branch’s activity. Offline snapshot branches have no inferred times. A compact GitHub author avatar precedes the timestamp, with contributor styling, a profile link and an initials fallback. “browse tree” comes first; SHA links and default/protected badges remain.

Right-aligned branch checks combine the latest check runs and legacy commit statuses for that immutable HEAD. Completed success, neutral and skipped checks count toward the numerator. Failure takes precedence over pending work; cancelled/stale results stay neutral. Accessible labels explain the icon and count. No checks and unavailable/incomplete results display a neutral dash, never a fabricated green `0/0`. Each endpoint must return its complete result set within the requested 100-record page; otherwise the status is unavailable. Checks and commit metadata fail independently and share the existing ten-minute cache.

`space.js` remains unchanged by the palette/template refresh. It generates 900 temperature-varied stars, an irregular five-color textured nebula and three rotating tracks with miniature stellar cores/coronas. Preserve the approved nebula’s geometry, spectrum, texture, opacity and native wrapper motion. The fixed field stays behind scrolling content until the opaque footer; the upright N and orbits remain hero-local. Reduced motion, hidden tabs and manual pause stop motion; cleanup cancels animations and timers. Missing animation APIs leave a static field. The 30fps timer cap is not an accelerated frame-rate guarantee; hardware-accelerated desktop performance remains unmeasured.

Stars use seven approximate blackbody tints from 3,000–20,000 K. NASA’s [stellar spectra explanation](https://science.nasa.gov/asset/webb/continuous-spectra-blackbody-curves-of-stars/) and [star types reference](https://science.nasa.gov/universe/stars/types/) inform the illustration. A faint-heavy sample uses logarithmic flux, compressed exposure and sparse bloom. Apparent sizes represent point-spread/exposure, not stellar diameters. There is no artificial twinkling, catalog/calibrated photometry or claim that camera drift represents physical stellar motion.

`assets/ngen-orbital-core.svg` contains the supplied N and unfilled frame; the fallback derives from the brand schematic without captions or a central fill. Keep these website-specific variants outside the brand masters.
